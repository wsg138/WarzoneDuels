# Public weekly duel results

Canonical main 480a365 (1.0.1) is the source base; installed 1.0.4 and the
pending team source lineage must be reconciled before production delivery.
Do not install the local 1.0.1 test artifact over the running team plugin.

The optional read-only APIs websiteWeeklyResults(start,end) and legacy
websiteWeeklyWins(start,end) run off-thread through the synchronized primary
analytics store. They never open or copy another live database. The interval is
half-open, at most seven days. Only counted non-draw match results qualify.

When participant records exist, each persisted winning player receives one
credit per match. Opponents and wagers are never returned. Legacy single-player
records remain supported; team records without winning participants fail closed.
Latest names come from qualified matches, with deterministic UUID tie ordering.
Full results are bounded to 500 winners; a 501st row makes complete=false.
Missing players are known zero only when a fresh complete current-week export
is available. Query timeout is five seconds; database errors remain unavailable.

Manual SPEAR applies; this canonical checkout has no EARS/state helper.
The initial winning-teammate regression failed before the repair. Real H2 tests
cover legacy windows/names, winning teams, draws/cancellations, missing team
credits, empty results and the completeness boundary. Native H2 results flow
through the actual MaceGuard signer and website SQLite ingest in a separate
synthetic contract check. No live match or reward is generated by these tools.

Local clean Maven verify passes (38 tests). This is source/fixture proof only;
canonical merges, network pins, clean runtime build and a real counted match
remain acceptance gates. This PR alone does not activate any server feature.
